1. OBJECTIVE
==================================================

Build the user-facing interface and workflow for the Solution Recommendation Engine™.

The UI must allow an authorized consultant or administrator to:

- Generate a Solution Recommendation Plan from an approved Growth Assessment
- Review the system-generated executive recommendation
- Review ranked recommendations
- Understand scoring and prioritization
- Review actions and dependencies
- Edit permitted Draft content
- Submit a plan for review
- Approve a plan
- Reopen an approved plan
- Regenerate a Draft or Reopened plan
- Archive a plan
- View recommendation activity
- Access plans from assessments, clients, projects, and dashboard locations

The experience must be clear, executive-friendly, practical, and consistent with the existing Viral Magic OS design.

7. GENERATION WORKFLOW
==================================================

From an approved Growth Assessment:

1. User clicks Generate Solution Plan
2. Show confirmation dialog explaining:
   - The plan will be generated from the approved assessment
   - Recommendations are deterministic and based on assessment findings
   - The plan will initially be Draft
3. Call the existing generate endpoint
4. Show progress state
5. On success, navigate to the new plan
6. On failure, show a clear user-safe error
7. If an active plan already exists, show View Existing Plan instead of creating a duplicate

Do not allow repeated clicking to create multiple plans.

10. REGENERATION WORKFLOW
==================================================

Regeneration is allowed only when backend status rules permit.

Before regeneration, show a strong confirmation dialog:

- Explain that the current active plan will be superseded
- Explain that a new plan version will be created
- Explain that the previous plan remains in history
- Require explicit confirmation
- Disable the button after submission

After success:

- Navigate to the new plan
- Show confirmation message
- Verify old plan displays Superseded
- Verify new plan displays Draft
- Provide history access where practical

Do not implement regeneration as an in-place overwrite.
