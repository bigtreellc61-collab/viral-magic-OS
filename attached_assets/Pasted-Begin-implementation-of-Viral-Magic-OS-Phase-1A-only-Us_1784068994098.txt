# 1. PRESERVE THE ARCHITECTURE

Follow the architecture plan already approved.

Preferred stack:

- TypeScript
- React
- Node.js
- PostgreSQL
- Reliable ORM
- Server-side validation
- Modular services
- Environment variables or Replit Secrets

Do not replace the approved architecture with a simpler static mockup.

Do not use temporary in-memory storage.

All settings and administrator records must persist after page refresh and application restart.

# 2. DATABASE FOUNDATION

Connect the app to Replit’s managed PostgreSQL database.

Create migrations for the Phase 1A tables required now:

- users
- roles
- user_roles or equivalent role relationship
- application_settings
- activity_records

You may also create framework-level migration metadata tables required by the ORM.

Do not create every future business table yet unless the architecture requires placeholder migrations.

Requirements:

- UUID or similarly robust primary keys
- Created-at timestamps
- Updated-at timestamps
- Soft-delete or archive fields where appropriate
- Foreign-key integrity
- Indexed fields where useful
- Server-side validation
- No hard-coded database credentials

Create a repeatable migration command.

Document how migrations are applied.

# 3. ADMINISTRATOR AUTHENTICATION

Create one secure Administrator login system.

Requirements:

- No public registration
- Login page
- Logout
- Protected application routes
- Password hashing
- Rate limiting or basic brute-force protection
- Secure session cookies
- Session expiration after 8 hours of normal use
- Rolling expiration while active
- Optional Remember Me checkbox
- Remember Me duration: 30 days
- Session invalidation after password change
- Unauthorized users must be redirected to login
- Server endpoints must also enforce authentication

Create the initial Administrator through one of these safe methods:

Preferred:
- Secure first-run setup flow

Acceptable alternative:
- Environment-variable-based administrator seed

Never hard-code a default email or password inside the source code.

Do not display private environment values in the interface.
